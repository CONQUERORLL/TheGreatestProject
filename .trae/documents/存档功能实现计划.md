# 三槽自动存档设计与实现

## 当前状态

游戏使用三个独立存档槽，主菜单的新局和继续游戏都先选择槽位。旧版 `user://save_run.json` 会在槽 1 为空时迁移到槽 1；迁移成功后才删除旧文件。

## 文件与版本

- 槽位文件：`user://save_slot_1.json` 至 `user://save_slot_3.json`
- 当前版本：`2`
- 兼容读取：版本 `1` 和 `2`
- 设置文件仍独立使用 `user://settings.cfg`
- 自动化测试必须先调用 `SaveRun.set_storage_root_for_tests(...)`，禁止操作正式槽位
- 旧档迁移由正式主菜单触发；测试存储根启用时会跳过迁移

## 安全检查点语义

正式存档表示“下一波开场快照”：

1. 新局完成角色、武器、道具和难度向导后，在主场景初始化玩家并原子覆盖所选槽的第 1 波快照；写入失败时保留旧档。
2. 普通波结束进入商店时，保存下一波快照。
3. 商店购买、出售、刷新和回血后重新保存下一波快照。
4. 点击下一波前必须保存成功；失败则停留在商店并提示。
5. 战斗、开场或升级阶段返回主菜单时不保存本波收益，恢复进入本波开场。
6. 死亡或胜利清除当前槽。

该语义避免保留本波收益后重复刷同一波，也避免未序列化货架时通过继续游戏免费刷新商店。

## 写入与恢复保证

- `SaveRun.save(...) -> bool`，调用方可以阻止在保存失败后离开安全点。
- 新数据先写入同目录 `.tmp`，刷新并重新读取验证后再替换正式文件。
- 替换时保留 `.bak`；正式文件损坏或缺失时读取层会尝试有效备份。
- 波次必须在 `1..Config.WAVES_TOTAL`，非法槽位不会映射到槽 1。
- 读取会验证数值有限性、玩家属性范围、武器数组和道具数量。
- 已卸载的 Mod 角色回退为内置角色；失效武器/道具会过滤，武器全失效时回退手枪。
- 恢复版本 2 的 `wave_start` 后直接启动对应波次，不重新打开商店。

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --path game --import
Godot_v4.7.2-stable_win64_console.exe --headless --path game res://tests/smoke_test.tscn
```

烟雾测试使用 `user://tests/smoke_run`，覆盖三槽隔离、精确数值校验、损档与备份恢复、v1 旧单槽迁移、主菜单选槽到向导、连续升级和检查点基础行为，并在成功或失败时清理测试槽。
