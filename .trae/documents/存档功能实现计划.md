# 存档功能实现计划（Brotato 式单槽自动存档）

## Context

游戏目前一旦退出就丢失整局进度（一局 10 波约 15-20 分钟），需要存档功能让玩家中途退出后能从主菜单"继续游戏"恢复。采用 Brotato 原版同款模式：**波次间（商店阶段）为安全点自动存档，死亡/胜利清档，主菜单提供"继续"入口**。不序列化战斗中的敌人/子弹（roguelite 惯例，恢复时从商店重开当前/下一波即可）。

## 存档设计

- **文件**：`user://save_run.json`（嵌套结构，JSON 比 ConfigFile 合适；与 settings.cfg 互不干扰）
- **单槽**：新档在首个存档点自动覆盖旧档（Brotato 行为）
- **内容**：
  ```json
  { "version": 1,
    "rng_a": 12345678,
    "run": { "wave": 3, "materials": 120, "kills": 88, "run_time": 421.5,
             "level": 5, "xp": 12, "level_queue": 0,
             "difficulty_id": "normal", "character_id": "potato",
             "loadout_weapon": "pistol", "loadout_item": "" },
    "player": { "hp": 76.0, "stats": {...13 项},
                "weapons": [{"type": "smg"}], "items_owned": {"i-boots": 2} } }
  ```
- **存档点语义**：`wave` = 接下来要打的波次编号。商店打开时 `shop_ui.open(w)` 的 w 是刚结束的波 → 存 `wave = w + 1`；战斗中返回主菜单存 `wave = 当前波`（重打当前波）。恢复时统一 `shop_ui.open(wave - 1)`（货架重摇，材料/属性/道具完整保留）。
- **清档时机**：死亡 / 胜利。
- **随机数**：保存 `GameRng._a`（mulberry32 单状态变量，直接读写），恢复后随机序列延续。
- **容错**：JSON 解析失败 / version 不符 → 视为无存档；`character_id`、武器、道具 id 不在 Registry（创意工坊内容被卸载）→ 回退 potato / 丢弃该条。

## 改动文件

### 1. 新增 `game/scripts/core/save_run.gd`（autoload `SaveRun`）
- `exists() -> bool`、`clear()`
- `save(next_wave: int, player: Node)` —— 从 GameState / player / GameRng 收集写入 JSON
- `restore(player: Node) -> int` —— 读档 + 校验 + 写回 GameState 字段 / player.hp / player.stats / player.weapons（cd 重置 0.3）/ player.items_owned / GameRng._a，返回 next_wave；返回 0 表示档无效
- 注意项目经验：跨脚本不用 class_name 静态类型，参数用弱类型 Node；autoload 直接互相引用（与现有 shop_ui 调 GameState/Sfx 风格一致）

### 2. `game/project.godot`
- `[autoload]` 段追加 `SaveRun="*res://scripts/core/save_run.gd"`（放在 Settings 之后）

### 3. `game/scripts/core/game_state.gd`
- 加 `var continue_pending := false`（主菜单"继续"→ main 场景一次性消费标志）

### 4. `game/scripts/main.gd`
- `_ready()`：开头分支——
  - `GameState.continue_pending == true`：`var nw := SaveRun.restore(player)`，`continue_pending = false`；nw > 0 时跳过 `GameState.start_run()` 与 loadout_item 应用，改为 `shop_ui.open(nw - 1)`；nw == 0（档损坏）则回退正常开局流程
  - 正常流程保持现状
- `_on_wave_ended(w)`：`shop_ui.open(w)` 后 `SaveRun.save(w + 1, player)`
- `_on_player_died()` / `_on_boss_killed()`：`SaveRun.clear()`
- `toggle_pause()` 所在文件内的 `_goto_main_menu()`：调用前若 phase 处于 PLAYING/INTRO/SHOP/PAUSED/LEVEL_UP（即本局进行中）→ `SaveRun.save(wave_manager.wave + (1 if 商店刚结束 else 0), player)`，简化为：SHOP 阶段存 `wave_manager.wave + 1`，战斗中存 `wave_manager.wave`
- 暂停菜单"返回主菜单"即走 `_goto_main_menu`，自然覆盖

### 5. `game/scripts/ui/main_menu.gd`
- `_build_home()`：按钮列表头部条件插入"继 续 游 戏"（`SaveRun.exists()` 时），副标题显示存档的"第 X 波 · 角色名"（读 JSON）
- 点击 → `GameState.continue_pending = true` → change_scene main.tscn
- 修复写死索引 `box.get_child(3).grab_focus()` → 改为按引用聚焦"开始游戏"按钮（插入继续按钮后索引会漂移）

### 6. `game/scripts/ui/shop_ui.gd`
- `buy()` / `_sell()` / `reroll()` / `heal()` / `next_wave()` 末尾调 `SaveRun.save(_wave + 1, player)`（next_wave 存新波进度），保证商店内任意操作后退出不丢

### 7. `game/tests/smoke_test.gd`
- 新增 `_check_save()` 段：
  1. 打完第 1 波进商店后断言 `SaveRun.exists()`
  2. 篡改 GameState.materials / player.hp / player.weapons 后用存档 JSON 数据还原断言字段一致（直接调用 save→改→restore 比对）
  3. `SaveRun.clear()` 后断言 `exists() == false`

## 验证

1. **重建缓存 + 冒烟**（项目经验：.godot 缓存丢失会 class_name Parse Error，先 --import）：
   ```
   D:\code\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game --import
   D:\code\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path game res://tests/smoke_test.tscn
   ```
   退出码 0 且输出 `SMOKE: PASS`
2. **手动闭环**（可选，用户实机验证）：
   - 开局打完第 1 波进商店 → 关闭游戏 → 主菜单出现"继续游戏（第 2 波 · 土豆）"→ 恢复后材料/属性/道具/等级与退出前一致
   - 商店买 1 件道具 → 退出 → 继续后道具在
   - 死亡/胜利后主菜单不再显示"继续"
3. **Android**：存档走 `user://`，APK 无需改配置；冒烟通过后可重新导出（命令已就绪）
