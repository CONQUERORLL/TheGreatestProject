# export/ · 打包脚本说明

> ⚠️ 这里是**版本库副本**（ 被 .gitignore 忽略，脚本放那里会丢）。
> 日常直接双击项目根目录  下的同名脚本即可。
> 若修改了脚本，记得把新版复制回 ，或反过来同步。


> 双击 `.bat` 即可打包，**不需要 AI 参与**。产物不入库（`export/` 在 `.gitignore` 里）。

## 脚本

| 双击这个 | 干什么 | 耗时 | 产物 |
|---|---|---|---|
| **`_打包exe.bat`** | 打包 Windows 版 | ~8~30s | `BrotatoLite.exe`（~105 MB，单文件） |
| **`_build_exe.bat`** | 同上（纯英文名，终端显示更稳） | ~8~30s | 同上 |
| **`_打包apk.bat`** | 打包 Android 版 | ~16~40s | `BrotatoLite.apk`（~28 MB，已签名） |

三个脚本内容基本一致：英文名副本 `_build_exe.bat` 是给「中文路径/终端乱码」场合兜底的，平时随便点哪个都行。

## 脚本会做什么

1. 检查 Godot 和项目目录是否存在 —— 找不到就报错并停下（不会误删东西）
2. 打印上一版产物的字节数，方便对比
3. 调用 Godot 无头导出，**全部输出写进日志文件**
4. 校验三件事：返回码为 0、产物存在、时间戳/体积更新
5. 打印 `SUCCESS` + 体积 + 时间 + 与旧版的体积差
   - ⚠️ 若字节数与上版**完全相同**，会提示 `NOTE : byte size identical` —— 这通常意味着**代码没改**，别以为打包失败了
6. exe 脚本最后会问一句「现在启动游戏试玩吗？」，15 秒不选默认不启动

**失败时**：脚本会暂停（`pause`）并自动打印日志末尾 30 行，窗口不会闪退，方便你截图给我。

## 日志

| 文件 | 内容 |
|---|---|
| `_build_log.txt` | exe 打包的完整 Godot 输出（每次覆盖，~200 行） |
| `_apk_build_log.txt` | apk 打包的完整 Godot 输出 |

打包有问题就把对应日志发我。

## 常见问题

**窗口一闪而过 / 什么都没发生**
说明脚本没跑起来。检查 `.bat` 是否被改成 LF 换行（必须是 CRLF + 无 BOM）。用文本编辑器另存为「Windows 换行符」即可。

**报 `[ERROR] Godot not found`**
Godot 路径变了。用记事本打开脚本，改顶部 `set "GODOT=..."` 那一行。

**报 `[ERROR] Project not found`**
项目移动了。改顶部 `set "PROJ=..."`。

**exe 打包成功但游戏跑不起来**
看 `_build_log.txt` 有没有 `ERROR` / `SCRIPT ERROR`。这类问题通常是 GDScript 编译错误，日志里会有行号。
