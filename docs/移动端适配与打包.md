## 二、UiMetrics 的设计基准（理解一切数字的前提）

**基准：让「1 UI 单位 ≈ 1 dp」**。目标 160 单位/英寸（`ui_metrics.gd:33 UNITS_PER_INCH := 160.0`），
靠改 `content_scale_factor = 720/(160×物理高)` 反推（`_compute_scale()` :78-88）。所以：

- **移动端**：`units_per_inch == 160` → **`dp(v) == v`（恒等）**，裸数字就是 dp，`48` 就是 48dp。
- **桌面**：`is_mobile == false` → 不设倍率，`units_per_inch` 退化成屏幕 DPI（常 96）→ **`dp(v) ≈ 0.6v`**，
  `dp(48)==28.8`、`dp(340)==204`、`dp(38)==22.8`（按钮反而变矮）。

**两类概念必须分开**（`ui_metrics.gd:24-25` 的注释也强调）：

| 用途 | 判据 | 说明 |
|---|---|---|
| **排布**（界面怎么分列） | `size_class()` :201 / `is_compact()` :211 | 档位 `CLASS_COMPACT_MAX=520`、`CLASS_MEDIUM_MAX=680`（:45-46）。⚠️ **平板是反例**：排布够宽（`expanded`）但纯触屏 |
| **人体工学**（触控目标多大、要不要 hover 提示） | `is_touch` :52 | `DisplayServer.is_touchscreen_available()`（:68），与倍率无关 |
| **要不要走整页布局** | `prefers_full_page()` :215 | ⚠️ 返回 `is_mobile or is_compact()`（:216）——**桌面窗口拉窄到 compact 也会返 true**，这是有意的 |

关键 API：`dp()` :136、`touch_min()` :142（=48dp）、`touch_at_least()` :146（**非触屏恒等返回原值**）、
`available()` :219（视口扣边距）、`safe_insets()` :162（四边兜底 `SAFE_MIN_DP=8.0` :40）、
`grid_columns()` :246、`card_grid()` :267。

## 三、⚠️ 桌面契约（改任何 UI 尺寸前必读）

> 这条已写在 `类土豆兄弟游戏开发规划.md:706`，是既有约定，本节只是复述并补上源码坐标。

1. **绝不裸用 `dp()`**。`dp()` 在桌面会缩到 ~0.6×，直接套会让桌面控件变小。
2. 需要「移动端变大、桌面不变」的地方，必须写成
   `UiMetrics.touch_at_least(UiMetrics.dp(X)) if UiMetrics.prefers_full_page() else X`
   （先例：`main.gd` 暂停面板 `act_h := touch_at_least(dp(38)) if compact else 44`）。
3. 判排布用 `size_class()`／`is_compact()`，**不要**用 `is_touch`；判人体工效用 `is_touch`。

## 五、冒烟覆盖

`tests/smoke_test.gd::_check_mobile_ui()`（定义 :7007，调用 :1038）——本轮新增。此前冒烟对 `UiMetrics`
**零覆盖**（`TouchControls` 另有既有断言 :1078-1083，与本条不重复）。

断言清单（每条都配反向对照，防「恒真」）：

| 断言 | 防的是什么 |
|---|---|
| `clamp_to_viewport(9999, 200×100) == 192,92` | 超出视口未裁剪 |
| 结果**不是恒等函数** | 函数没生效也能绿 |
| 小尺寸（10×20）不被放大 | 误把「夹取」写成「归一」 |
| 极小视口（10×10）下界 ≥ 1 | 返回 0 → 气泡不可见且落点夹取反向 |
| `prefers_full_page() == false`、`size_class() == "expanded"` | 桌面排布分支整体切错 |
| `card_grid` 桌面**原样返回** `want`、cols==3 | 桌面卡阵尺寸被改 |
| `touch_at_least(30) == 30`（非触屏恒等） | 桌面被抬尺寸 |
| 气泡四个上限 == 原常量 `MAX_W/MAX_H/DOCK_W/DOCK_MAX_H` | 窄屏收缩漏到桌面 |
| `safe_insets()` 四边 ≥ `dp(SAFE_MIN_DP)` | 刘海 API 不可用时退化成 0 |
| `available()` 真的扣了边距（0 < avail < viewport） | 「自适应」按全屏算 |
| `grid_columns(2000,…)==3` 且 `(200,…)==1` | 恒返回 1 / 恒返回 n |

> 四个上限写成 `static` 是**为了这条断言不实例化 Control**——测试里 `new` 一个 Control 会往 ObjectDB 塞对象，
> 把退出时的泄漏计数搅浑，真泄漏反而看不见。实测泄漏数 9 个与是否加这段断言无关（`--verbose` 显示是
> `AudioStreamWAV`/`AudioStreamPlaybackWAV`，强制退出不释放播放流，**非失败噪音**）。

打印：`SMOKE: mobile ui metrics OK（expanded / caps max_w=340.0 max_h=260.0 dock_w=360.0 dock_max_h=340.0）`

| 项 | 实测值 | 备注 |

| 启动入口 | **`activity-alias` `com.godot.game.GodotAppLauncher`**，带 `action.MAIN` + `category.LAUNCHER` + `DEFAULT`，`exported=true` | ⚠️ 因为是 activity-alias，`aapt dump badging` **不会打印 `launchable-activity` 行**——别据此误判「没有启动图标」。桌面有图标、可正常启动 |

### ⚠️ 已知限制：产物只有 `arm64-v8a`
预设 `arch/armeabi-v7a=true`、`arch/arm64-v8a=true`，但产物**只含 arm64**。

- 已排除的可能：**不是模板缺库**（模板里四种 ABI 都带）；**不是预设没被读**（同预设的包名/版本/keystore/权限**全部生效**）。
- 已做的对照实验：把 `arch/x86_64` 翻成 `true` 再导一次 → 产物**仍然只有 arm64** ⇒ **headless 导出忽略 `arch/*` 开关**。
  （实验脚本 `game/tools/_abi_probe.py` 可复跑。）
- 后果：32 位老机 / x86 模拟器装不上；**Android 7.0+ 的 64 位手机不受影响**，Google Play 也强制 64 位。
- 未定位到 Godot 内部原因。若要出 32 位包，需要用编辑器 GUI 导出或另想路径。
- 核验「改动进包了没」要按 **`.gdc` + `.gd.remap`** 找（**不是 `.gd`**）；包内**脚本内容被压缩**、标识符搜不到，
  但**路径表是明文**（可搜 `mods_disabled` 校验布局）。
