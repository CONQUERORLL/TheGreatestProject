# 版本号规则

> 用户 2026-09-19 定下的机制。**当前版本 `v0.50.0`**。

## 一、规则

语义化版本 `MAJOR.MINOR.PATCH`：

| 位 | 名称 | 什么时候涨 |
|---|---|---|
| **MAJOR** | 大版本 | **仅当用户明确宣布「正式发布」时**才涨（涨到 `1.0.0`）。日常绝不涨 |
| **MINOR** | 中版本 | **机制修改** —— 新增/改变系统、新玩法、UI 结构、重构、数据模型变更 |
| **PATCH** | 小版本 | **数值调整** —— 改伤害/血量/价格/概率/倍率等，不动机制 |

大版本涨时，中版本与小版本**归零**（`0.x.y` → `1.0.0`）。

## 二、怎么用（给我或给你自己）

1. **改完代码、准备提交时**，判断这次改动是「机制」还是「数值」。
2. 去 `game/scripts/core/config.gd` 顶部改 `VERSION_MAJOR / MINOR / PATCH` 三个常量。
3. **版本号改动与代码改动放在同一个提交里**。
4. 菜单右下角会自动显示新版本号（读的就是那三个常量，无需改别处）。

> ⚠️ 版本号**不随自动构建变化** —— 它由人工维护，这样"哪个版本改了什么"才说得清。
> ⚠️ 判断标准：**只要动了机制就涨中版本**，哪怕这次改动里也夹带了数值。
> 只有"纯数值、零机制"才涨小版本。

## 四、口径说明（供复核）

**判定原则**
- 引入新 `.gd` 系统文件 / 重构 UI 接线（≥100 行非数值代码）→ **机制**，即便标题带"平衡"。
- 改动集中在 `config.gd` 常量表、无新文件 → **数值**。
- 纯 docs / chore / .uid / merge → **不计版本号**。

**保守归并的几处判断**（这是本表主观性最强的部分，都记在这里以便复核）
- `90792fe` + `10a12aa`：同属一次移动端适配，但分两次提交 → 按各自机制算（`0.3.0`/`0.4.0`）。
- `1287fc9`：标题自报"数值平衡"，但 `main_menu.gd` 改了 634 行 → 按机制计。
- `e600854`：标题主打"平衡"，但新增 `nav.gd`(86行)+`ui_metrics.gd`(286行) → 按机制计。
- `d7ca39e` + `0a4868d` + `6cc379e`：地形#6 的三连改 → **只首次算机制**，后两次算小版本。
- 三条同族 bug 修复（`4cb3623`/`b1de04a`/`50327ac`）→ 按小版本计。

**若口径不同，终值会落在 `0.50.x ~ 0.61.x` 之间** —— 差异全部来自上述判断，核心机制判定均有 `git show --stat` 支撑。
