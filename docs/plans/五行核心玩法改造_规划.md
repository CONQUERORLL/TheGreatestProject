# 「五行核心」玩法改造规划

> **目标**：把五行从「状态层的附属标签」提升为「内容与玩法的顶层属性」——
> 所有武器、道具、角色、敌人都带明确五行，五行生克成为核心玩法驱动。
>
> **决策基线**（2026-09-14 与沧溟确认）：
> 1. **两层咬合** —— 属性对抗（改伤害）+ 状态反应（管爆发），两者互相触发
> 2. **五行可变** —— 武器/道具属性可被道具与角色特性**反转、循环改变**；角色五行由自身特性决定
> 3. **温和克制** —— 相克约 +25~35%，相生不减成
>
> 本文是实施计划，不是讨论稿。带「待确认」标记的地方需要拍板后才能动工。

---

## 〇、一条铁律（先读）

**现有五行反应系统是资产，不是包袱，禁止推翻重做。**

`Config.REACTIONS` 的 10 条反应（5 生 + 5 克）已经具备：数据驱动、`Registry.find_reaction()`
可被 mod 覆盖、`MAX_REACTION_DEPTH` 递归护栏、`REACTION_BURST_CAP_MULT` 伤害护栏、
粒子/震屏/sfx/图鉴解锁/法宝改写钩子（`ArtifactSystem.patch_reaction_effect`）。

本次改造**在它之上长出来**，而不是替换它。任何"不如重写"的冲动都请先读这一节。

## 一、现状体检

### 1.1 已有资产（复用）

| 组件 | 位置 | 状态 |
|---|---|---|
| 五行集合 | `Config.ELEMENTS` | 5 个，字母序 `earth/fire/metal/water/wood` |
| 状态→五行 | `Config.STATUS_ELEMENT` | 6 状态全覆盖（burn→fire / poison→wood / bleed→metal / freeze+slow→water / stun→earth） |
| 配色 / 中文名 | `ELEMENT_COLOR` / `ELEMENT_NAME` | 完整，图鉴与 HUD 已在用 |
| 反应表 | `Config.REACTIONS` | 10 条，key = 两五行字母序拼接 |
| 反应查询 | `Registry.find_reaction(a, b)` | mod 可覆盖 |
| 伤害护栏 | `REACTION_BURST_CAP_MULT = 12.0` | 有 |
| 归属样板 | `Config.ARTIFACTS` | **18/18 带 `element`**，`params.element` 已用于触发器过滤 |
| 亲和系统 | `Config.affinity_tags()` / `affinity_mult()` | 从数据自动推导标签 → 商店/升级加权保底 |
| 表现 | `codex.gd` 五行组合页 / `hud.gd` 反应折叠页 | 有 |

### 1.2 三个断裂（要补的）

**① 归属断裂**
- 武器 29 把：**无 `element`**。靠 `status` 间接关联五行，其中 **7 把连 `status` 都没有**
  （手枪 / 冲锋枪 / 霰弹枪 / 加特林 / 榴弹炮 / 双管神射 / 蜂巢风暴 / 斩魄刀等）→ 五行体系里的"幽灵武器"
- 道具 58 个：无 `element`，靠 `on_hit_*` 间接
- 角色 12 个：无 `element`，"火系"仅是 `trait.status = "burn"` 的隐式结果
- 敌人 27 个：无 `element`，"五行阵营"靠 id 前缀（`fire_imp`）+ 颜色隐式表达

**② 机制断裂**
现有相生相克**只发生在「两个状态相遇」时**（`apply_status` → `check_reactions`）。
没有「攻击方五行 × 受击方五行」的对抗层 —— 火系武器打木系怪，现在零特殊效果。

**③ 数值断裂**
玩家 `stats` 只有泛化的 `status_dmg_mult`，**没有 per-element 加成**，
因此游戏无法识别"我这套是火系流"，构筑没有主线。

### 1.3 一条设计约束（必须牢记）

Roguelite 玩家**不能自由换属性**（武器靠抽、角色靠选）。
固定归属下做硬克制（宝可梦式 2x/4x）必然退化成「抽到克制就通关、抽不到就暴毙」的运气游戏。

**→ 这是"五行可变"（决策 2）存在的根本理由：把运气变成策略。**
—— 但这条约束并没有消失，而是**转移**了：动态五行必须是**可获得、可控**的，
否则玩家依然只能被动接受抽到的属性。见 §2.2.3 的获取渠道设计要求。

## 二、设计

### 2.1 三层架构

```
L3 构筑层   五行亲和（本局五行倾向识别）· HUD/商店/图鉴的五行呈现
              ↑ 读取
L2 机制层   ① 属性对抗（attack_element × target_element → 伤害修正，有方向）
            ② 状态反应（现有 REACTIONS，管爆发）
            两者咬合：对抗可触发反应、反应可改属性
              ↑ 读取
L1 归属层   element 字段（武器/道具/角色/敌人）
            + 动态五行（转属 / 反转 / 轮转）
```

### 2.2 L1 归属层

#### 2.2.1 `element` 字段规范

- 取值：`Config.ELEMENTS` 之一，或 `""`（无属性）
- 缺省：`""`（向后兼容 —— mod 内容不写 element 也不会崩，走"无属性"分支）
- 校验：`Registry` 注册时校验，非法值 warn + 回落 `""`（**不拒绝加载**，与现有未知 `fx` 键的处理口径一致）
- 图鉴：`element` 非空才显示五行分组与五行徽记

#### 2.2.2 五行归属表（草案）

**武器 29 把** —— 按"武器给人的属性直觉"归属，优先复用已有 `status` 的五行：

| 五行 | 武器 |
|---|---|
| 火 | 火焰喷射器、赤焰折扇、火焰长剑、火箭筒 |
| 水 | 霜冻法杖、玄冰新星、霜牙重锤、沥青长鞭(减速→水) |
| 木 | 毒牙匕首、青藤缠索、疫病连弩 |
| 金 | 砍刀、太刀、金铃破空、狙击枪、磁轨炮、鎏金权杖(金→?) |
| 土 | 震雷法锣、混沌重锤、鎏金权杖 |
| **待定** | 手枪 / 冲锋枪 / 霰弹枪 / 双管神射 / 蜂巢风暴 / 加特林 / 榴弹炮 / 斩魄刀 |

⚠ **待定项是本次改造的设计难点**：这 8 把是"纯物理"枪械，没有天然的五行直觉。
三个选项见 §7 待确认 #1。

**道具 58 个** —— 分两类，只给"有属性倾向"的标，通用属性道具保持无属性：
- 有属性：`余烬`(火) / `毒囊`(木) / `玄冰诀`(水) / `血战令`(金) / 土系道具…
- 无属性（保持 `""`）：`番茄` / `弹药袋` / `弹簧` / `运动鞋` 等纯数值道具
  —— **理由**：给通用道具硬塞五行会污染构筑亲和，且玩家无法理解"为什么弹簧是火系"

**角色 12 个** —— 5 个门派修士天然对应五行；其余 7 个（枪手/剑客/武僧等）为**无本命五行**：

| 角色 | 本命五行 | 依据 |
|---|---|---|
| 焚天祭司 | 火 | trait.status = burn |
| 青囊药王 | 木 | trait.status = poison |
| 太白剑客 | 金 | 剑道 / trait 偏暴击 |
| 沧海鲛人 | 水 | trait.status = freeze |
| 铁卫 | 土 | trait 偏防御 |
| 其余 7 个 | `""` | 无本命，但可被五行道具/天赋赋予 |

**敌人 27 个** —— 分两档：

| 档位 | 敌人 | element |
|---|---|---|
| 基础 10 个 | grunt / runner / tank / shooter / swarm / bomber / wizard / shadow / guard / chest_guard | `""`（无属性） |
| 五行阵营 10 个 | fire_imp / fire_shaman / wood_sprite / vine_beast / metal_puppet / blade_monk / water_nymph 等 | 按 id 前缀显式标定 |
| BOSS 6 个 | 轮换 | 各带一个主属性（**待确认 #2**） |

**为什么基础敌人保持无属性**：W1-2 是教学期，玩家不应该在还没理解五行时就被克制惩罚。
五行敌人从 W3+ 开始混入，与现有"五行阵营"的引入节奏一致。无属性 = 对抗倍率恒 1.0。

#### 2.2.3 动态五行（决策 2 的核心，本次改造的灵魂）

**三种操作**（作用于"某个武器槽 / 某个道具"的当前五行）：

| 操作 | 语义 | 例子 | 实现 |
|---|---|---|---|
| `set` 转属 | 直接指定目标五行 | 「焰纹符」：把当前武器转为火 | `element = target` |
| `reverse` 反转 | 变为**克己者**（谁克我，我便化为何） | 火 → 水（水克火） | 查 `REACTIONS` overcome 关系反推 |
| `cycle` 轮转 | 沿**相生链**推进一步 | 木 → 火 → 土 → 金 → 水 → 木 | 相生环偏移 +1 |

⚠ `reverse` 的方向定义有歧义（"克己者" vs "己克者"），见 §7 待确认 #3。

**数据承载**：不动 `WEAPONS` 常量表，改为在**局内运行态**记录覆盖值 ——
`player.weapon_elements[slot] = "fire"`，读取时 `当前五行 = 覆盖值 或 武器基表值`。
理由：`Config.WEAPONS` 是静态真值表（mod 也读它），运行时改写会污染存档与 mod 语义。

**获取渠道设计要求（关键）**：
动态五行**必须让玩家能主动规划**，而不是随机白送。要求：
- 至少 1 件**商店常驻**的转属道具（可按需购买，不依赖抽）
- 至少 1 个角色的特性/技能提供**轮转**能力（如"五行环"每波轮转一次）
- 事件卡提供"以属性为代价换收益"的取舍（符合现有事件卡设计语言）
- **反转**作为稀有/高价值效果，放在法宝或角色大招，不泛滥

### 2.3 L2 机制层

#### 2.3.1 属性对抗（新增）

**方向性**：五行相克是**单向**的（火克金 ≠ 金克火），而现有 `REACTIONS` 的 key
是**无方向**的（`reaction_key()` 做了排序）。这是一个必须解决的矛盾。

**解法**：不新建表，而是给现有 10 条反应**补一个方向字段**：

```gdscript
# 现状（无方向）
"fire+metal": { "id": "fire_metal", "type": "overcome", ... }

# 新增字段（显式化方向 —— 注意 id 命名其实已经隐含了）
"fire+metal": { "id": "fire_metal", "type": "overcome",
    "from": "fire", "to": "metal",        # 火克金：火打金占优
    "counter_dmg_mult": 1.30,             # 克方伤害倍率
    "countered_dmg_mult": 0.85,           # 被克方伤害倍率
    ... }
```

- `from` / `to` 的取值规律与现有 `id` 命名一致（`wood_fire` = 木生火、`fire_metal` = 火克金）
  → **是显式化，不是新发明**，不会与现有数据冲突
- `counter_dmg_mult` / `countered_dmg_mult` 由 `type` 与 §2.3.3 的数值表推导

**对抗判定**（每次伤害结算）：

```
攻击方五行 A，受击方五行 D
若 A 或 D 为空  → 倍率 1.0（无属性不参与对抗）
若 A == D       → 倍率 1.0（同属性无相生相克）
否则查 reaction_key(A, D)：
  · 命中且 type == overcome：
      若 A == from → 相克（克方）→ +X%
      若 A == to   → 被克        → -Y%
  · 命中且 type == generate：相生 → 温和加成（见下）
  · 未命中 → 1.0
```

#### 2.3.2 与状态反应的咬合（决策 1）

两层不是并列，而是**互相触发**：

| 方向 | 机制 |
|---|---|
| 属性对抗 → 状态反应 | 相克命中时，**额外施加该行的对应状态**（火克金 → 附加燃烧）。这让"属性对"自然滚出"状态对"，从而触发原有反应 |
| 状态反应 → 属性对抗 | 反应触发后，给该敌人挂 `element_exposed`（元素暴露）短窗，期间受该反应的**两个五行**攻击时倍率提升 |
| 动态五行 → 状态反应 | 武器转属后，其施加的状态随之改变（火系武器转水 → 施加冰冻而非燃烧）。**注意**：这会让 `on_hit_*` 类道具失效或换向，见 §5 风险 |

**设计意图**：属性对抗负责**稳定的日常输出**，状态反应负责**爆发的上限**。
玩家不用两条线各堆一半，而是"选对属性 → 自然滚出状态 → 自然打出反应"。

#### 2.3.3 数值（温和，决策 3）

| 关系 | 攻击方倍率 | 说明 |
|---|---|---|
| 相克（克方） | **×1.30** | 主收益。玩家"选对属性"的回报 |
| 被克（被克方） | **×0.85** | 轻惩罚。不到 1.0 以下太多，避免"选错就废" |
| 相生 | **×1.10** | 温和奖励，鼓励五行搭配而非单一堆叠 |
| 无属性 / 同属性 / 未命中 | ×1.00 | 恒定 |

**为什么是 +30% / -15%**：
- 相克 +30% ≈ 一件优质道具的收益量级 → 值得追求，但不是"没有就打不过"
- 被克 -15% 远小于 +30% → **选错的代价可控**，符合"温和引导"
- 相生 +10% 低于相克 → 明确"克"是主旋律，"生"是搭配奖励

数值集中放 `Config`（与 `REACTION_BURST_CAP_MULT` 同口径），便于整体调参。

**护栏（必须做）**：
- 倍率上限：总倍率 `clamp(0.5, 2.0)` —— 防止动态五行 + 法宝 + 反应叠出乘算爆炸
- 多段命中的高频武器（加特林 0.06s CD）不额外放大，倍率**按次**结算即可（与现有 DPS 曲线同口径）
- 相克伤害**不吃** `REACTION_BURST_CAP_MULT`（那是反应专用护栏），但要走 `dmg_cap_pct`
  （BOSS 单次伤害上限），否则磁轨炮会秒 BOSS

#### 2.3.4 伤害管线接入点

现状：`enemy.take_damage(dmg, crit, dot)` —— **不带攻击方五行**。

改造（**签名向后兼容**）：

```gdscript
func take_damage(dmg: float, crit: bool, dot: bool = false, element: String = "") -> void:
    ...
    var final_dmg := dmg * ArtifactSystem.execute_damage_mult(player, self) \
        * _damage_taken_mult() \
        * Config.element_counter_mult(element, self.element)   # ← 新增乘区
```

调用点改造（`element` 由武器/载荷携带）：
- `bullet.gd` / `enemy_bullet.gd`：`roll_data` 增加 `element` 字段（子弹已在用 `roll_data` 承载伤害载荷）
- `player.gd`：`_damage_roll()` 输出里加 `element`（读 `weapon_elements[slot]`）
- `player.gd` 近战 / 光环 / 技能：各自从武器或角色本命五行取 `element` 传入
- `explosion.gd`：从触发它的子弹继承 `element`
- 状态 DoT（`enemy._tick_statuses`）：DoT 的五行 = **该状态的五行**（`STATUS_ELEMENT`），天然成立

**注意**：`dot = true` 的通道（状态 DoT）**不应**再吃属性对抗倍率 —— 否则"火 DoT 打在木怪身上"
会二次放大，且与状态设计冲突。建议：**属性对抗只作用于直接伤害（dot == false）**。

### 2.4 L3 构筑层

#### 2.4.1 五行亲和（复用现有机制）

现有 `affinity_tags()` 产出的标签是**状态名 + 形态名**（burn / melee / aoe / speed / multi）。
改造：**追加五行标签**（`el_fire` / `el_water` …），与现有标签并存。

- 武器：`element` 非空 → 打 `el_*` 标签
- 角色：本命五行 → 打 `el_*` 标签
- 道具/升级：`element` 非空 → 打 `el_*` 标签

收益：商店/升级的**保底契合项**会自动向"本局五行主线"倾斜，
玩家会自然感觉到"我这局在走火系"——**这就是沧溟要的"围绕五行打造"的落地**。

`AFFINITY_MAX_TAGS = 3` 的现有护栏保持不变（防止池子被锁死）。

#### 2.4.2 表现层

| 位置 | 呈现 |
|---|---|
| HUD | 当前主要五行倾向（按武器槽五行计数取众数）+ 相生相克速查 |
| 商店 | 道具/武器卡片显示五行徽记；转属道具给显著位置 |
| 图鉴 | 新增"五行"总览页（现有反应页升级）；武器/道具/敌人详情显示五行 |
| 战斗 | 相克命中飘字变色 + 短促音效（**不要**做成大特效，避免与状态反应抢注意力） |

**关键**：克制的**战斗反馈必须克制**。相克是"日常输出"，如果每次都弹大特效，
玩家会疲劳，也会让真正的状态反应（爆发）失去存在感。

## 四、分期计划

按"每期可独立验证、每期都能跑通冒烟测试"切分。

### Phase A：归属层（地基）
1. `Config.REACTIONS` 补 `from`/`to`/倍率字段 + `element_counter_mult()` 纯函数
2. 武器 29 / 道具 58 / 敌人 27 / 角色 12 的 `element` 标注
3. `Registry` 校验 + 缺省回落
4. 冒烟：断言每个 `element` 合法、每个 REACTIONS 条目 `from`/`to` 与 `id` 命名一致

**验收**：所有内容有明确五行（或显式无属性）；`SMOKE: PASS`

### Phase B：属性对抗（核心机制）

## 五、风险与护栏

| 风险 | 说明 | 对策 |
|---|---|---|
| **最优解坍缩** | 玩家发现"轮转到某属性就能通吃" | 敌人五行按波次轮换；`element_exposed` 只对反应的两种五行生效；Phase E 专项检查 |
| **动态五行让 `on_hit_*` 道具失效** | 火系武器转水后，`余烬`（命中 20% 点燃）与武器属性冲突 | 明确规则：**道具施加的状态不受武器属性影响**（道具是"附加效果"而非"武器属性"）。需在 UI 说明，否则玩家困惑 |
| **乘算爆炸** | 相克 × 法宝 × 反应 × 暴击叠出秒杀 | 总倍率 `clamp(0.5, 2.0)`；相克伤害走 BOSS `dmg_cap_pct` |
| **精英/BOSS 被属性针对** | BOSS 带固定属性 → 玩家轮转到克制属性即可 | BOSS 属性**每波轮换**（`攻击方不能靠单一属性吃穿 6 个 BOSS`） |
| **数值失衡** | +30% 在 DPS 曲线上的实际影响未知 | 复用 `docs/武器DPS体检表.md` 与 `tools/dps_audit.py` 重算，不靠拍脑袋 |
| **文档再次漂移** | 本次改动面极大，极易出现文档落后于代码 | 所有数值集中 `Config`；内容量速查由 `tools/content_manifest.py` 生成，**不手抄** |

## 七、待确认问题（拍板后才能动工）

**#1 纯物理枪械的五行归属**（8 把：手枪/冲锋枪/霰弹枪/双管神射/蜂巢风暴/加特林/榴弹炮/斩魄刀）
- 选项 A：全部归**金**（金属器械最直观，且能吃到"金→流血"的现有链路）
- 选项 B：按武器气质分散（狙击/磁轨=金、霰弹/榴弹=火、加特林=木…）
- 选项 C：**保持无属性**，作为"不参与五行博弈"的中立选择存在
- 我的倾向：**A**。理由是"金"在现有体系里已有"流血"链路（`blade` 系武器多为金），
  且金系目前武器偏少，正好补齐。选项 C 会让 8 把武器变成"五行体系的二等公民"。
  但如果你希望保留一批"无色武器"作为新手的稳定选择，C 也成立。

**#2 BOSS 是否带五行**
- 带（我倾向）：让 BOSS 战也有属性博弈，且属性每波轮换防止针对
- 不带：BOSS 保持中立，考验纯操作与构筑，不掺属性因素

**#3 `reverse`（反转）的方向语义**
- "**克己者**"：火 → 水（水克火）—— 语义是"以被克之身反制"，越打越被动转主动
- "**己克者**"：火 → 金（火克金）—— 语义是"乘胜追击"
- 我倾向"克己者"：它构成一个**自反的环**（反转两次回原位，因为克的克是双方互换…需实测验证封闭性），
  机制上更"反制"，也更符合"反转"的字面直觉。

**#4 相生是否也要有对抗倍率**
- 当前设计给了 +10%。若你希望"生"只体现在状态反应层（不参与伤害），
  则对抗层只保留"克/被克"两种，相生倍率恒 1.0。我倾向保留 +10%，让五行的两条关系都有存在感。
